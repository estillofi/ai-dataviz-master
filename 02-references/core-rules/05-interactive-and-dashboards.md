# Ядро 5. Интерактивные визуализации и небольшие дашборды

## Основания

- Дашборд (по определению Stephen Few) — визуальное представление самой важной информации для достижения одной или нескольких целей, собранное на одном экране, чтобы её можно было отслеживать с одного взгляда.
- Из этого следует: меньше блоков, чёткая иерархия, ничего декоративного, главное в верхнем левом углу.
- Интерактивность нужна, чтобы **ответить на вопрос читателя**, а не чтобы показать технику. Историю нужно понимать и без кликов.

## Анатомия дашборда

```
[Заголовок-вывод]
[Подзаголовок: что, период, данные на дату]
[Фильтры: ≤ 2-3]
[KPI-карточки: 3-5]
[Основные графики: 2-4]
[Источник · Примечания]
```

- Блоков не больше 7 на экран. Если больше, раздели на вкладки или на несколько дашбордов.
- Читать сверху вниз и слева направо: главное сверху слева.
- Сетка 12 колонок или 2-3 столбца, отступы одинаковые.
- Один акцент на страницу.
- Заголовок дашборда пересчитывается из данных (как в `assets/dashboard-skeleton.html`).

## KPI-карточка

| Элемент | Правило |
|---|---|
| Название | Короткое, термин из глоссария |
| Значение | Крупно, единицы указаны |
| Сравнение | С чем сравниваем (прошлый период, план). Знак, стрелка и слова, не только цвет |
| Спарклайн | Необязателен, без осей, показывает форму тренда |
| Статус | Только знак + слово («ниже плана»), не светофор |

## Интерактивность: бюджет

| Разрешено по умолчанию | Только по запросу владельца | Не использовать |
|---|---|---|
| Подсказка при наведении и фокусе (дополнение, не единственный источник) | Масштабирование и панорама | Анимации ради эффекта |
| Подсветка выбранного элемента, остальное приглушено | Кисть и выделение области | 3D-вращение |
| Переключатели (сегмент, период) ≤ 2-3 | Drill-down на один уровень | Автоплей |
| Сортировка по клику | Экспорт CSV, PNG | Бесконечная прокрутка |
| Таблица данных (`<details>`) | Сохранение состояния фильтров | Скрытие важных данных за кликом |

Правила:
1. Состояние по умолчанию уже рассказывает историю.
2. Все фильтры меняют **все** блоки, и это сказано в подзаголовке.
3. Любое действие доступно с клавиатуры. Фокус виден.
4. Подсказка содержит значения, а не новую информацию.
5. Состояния: загрузка, пусто, ошибка, мало данных. Для каждого есть понятное сообщение.
6. Сброс фильтров всегда доступен.
7. Дата обновления данных видна.

## Технические ограничения

- Один HTML-файл, данные константой, цвета из токенов.
- Внешние скрипты только из доверенного CDN и только с зафиксированной версией; если не нужны, не подключай.
- Ванильный SVG для простых графиков. Для > ~2000 элементов Canvas или агрегация.
- Нет `localStorage` и внешних запросов, если среда их не разрешает (проверь окружение).
- Адаптивность: проверка на 375px и 1280px; на телефоне блоки в один столбец, подписи сокращаются.
- Печать: фон белый, цвета сохраняются (`print-color-adjust: exact`).

# Ядро 1. Честность данных и восприятие

Ядро одинаково для всех команд и брендов. Стиль, цвет и форма могут меняться. Эти правила не меняются.

## Основания

| Принцип | Источник |
|---|---|
| Хорошая визуализация правдива, функциональна, красива, содержательна и проясняет картину | Alberto Cairo, *The Truthful Art* (2016) |
| Графическая честность: «фактор лжи» = размер эффекта на графике / размер эффекта в данных. Значение далеко от 1 (за пределами ~0.95-1.05) означает заметное искажение | Edward Tufte, *The Visual Display of Quantitative Information* (1983) |
| Точность чтения убывает: позиция на общей шкале → позиция на несовпадающих шкалах → длина → угол и наклон → площадь → объём, плотность, насыщенность цвета → оттенок | Cleveland & McGill (1984); воспроизведено Heer & Bostock (2010) |
| Обобщение и практика: серый по умолчанию, прямые подписи, вывод в заголовке, слой аннотаций | Cole Nussbaumer Knaflic, *Storytelling with Data*; Claus Wilke, *Fundamentals of Data Visualization*; практики отдела графики NYT |

## Иерархия кодирования (что выбирать для главного числа)

| Ранг | Канал | Пример | Для чего |
|---|---|---|---|
| 1 | Позиция на общей шкале | Точки, линии, столбцы от одной базы | **Главное числовое сообщение** |
| 2 | Позиция на разных шкалах | Малые множители (small multiples) | Сравнение групп |
| 3 | Длина | Столбцы | Сравнение величин |
| 4 | Угол, наклон | Pie, donut | Не использовать для сравнения |
| 5 | Площадь | Пузырьки, treemap | Только как вторая переменная |
| 6 | Насыщенность цвета, плотность | Тепловые карты | Общий паттерн, не точные значения |
| 7 | Оттенок | Цвет категории | Только для категорий |

**Правило:** самое важное число кодируй позицией или длиной. Никогда площадью, углом или цветом.

## Непреложные правила честности

| № | Правило | Как проверить |
|---|---|---|
| R1 | Столбцы и области начинаются с нуля | Нижняя граница оси = 0 |
| R2 | Размер круга или квадрата пропорционален значению по **площади**: радиус = k·√значения | Удвоение значения = удвоение площади |
| R3 | Сравниваемые значения на одной шкале. В small multiples одинаковые оси | Диапазон осей совпадает |
| R4 | Двойных осей Y нет (в одном графике две шкалы создают ложные корреляции). Решение: два графика друг под другом или индексация к базе (=100) | Одна ось Y |
| R5 | Нет 3D, перспективы, теней, «объёмных» столбцов | Только плоские формы |
| R6 | Pie и donut по умолчанию не используются. Замена: отсортированные горизонтальные столбцы | Нет секторов |
| R7 | Ось времени с равными интервалами. Пропущенные периоды показаны, не склеены | Даты идут равномерно |
| R8 | Пропуски: разрыв линии. Прогноз и оценка: пунктир и подпись «прогноз» или «оценка» | Пропуск не соединён линией |
| R9 | Окно времени не выбирается ради нужного эффекта. Показан достаточный контекст. Если окно обрезано, причина названа | В подзаголовке указан период |
| R10 | Сглаживание, агрегация, скользящее среднее, пересчёт валют объявлены в примечании | Есть строка «Примечание» |
| R11 | Для долей и процентов указана база (n или знаменатель). Проценты разных баз не сравниваются напрямую | Рядом с процентом есть n |
| R12 | Корреляция не подаётся как причина. Заголовок не содержит «из-за», «благодаря», если причинность не доказана | Нет причинных глаголов без обоснования |
| R13 | Неопределённость показана: диапазон, интервал, малая выборка. При n ниже порога число не показывается как процент | Малые n помечены |
| R14 | Округление единообразно, суммы сходятся, единицы указаны | Единицы есть в подзаголовке или первой подписи |
| R15 | Источник, дата данных и метод указаны всегда | Есть «Источник» и «Данные на» |
| R16 | Категории отсортированы по значению, кроме естественного порядка (время, шкалы, возрастные группы) | Порядок осмысленный |
| R17 | Выбросы не подрезаются и не прячутся. Их объясняют или помечают | Все точки видны |
| R18 | Мало данных (≈ меньше 4 значений): не рисуй график, покажи число или таблицу | — |
| R19 | Масштаб отражает реальность: не растягивай оси, чтобы тренд выглядел круче, не сжимай, чтобы скрыть | Соотношение сторон разумно |
| R20 | Если данные не позволяют ответить на вопрос, так и скажи. Не заполняй пробелы догадками | В ответе названы ограничения |

## Тест перед выдачей (10 вопросов)

1. Главное число закодировано позицией или длиной?
2. Столбцы от нуля?
3. Одна шкала для всего, что сравнивается?
4. Нет двойной оси, 3D, pie, теней?
5. Пропуски и прогнозы помечены?
6. Заголовок говорит то, что показывают данные, и не больше?
7. Указаны единицы, источник, дата данных, периметр (кто и что входит)?
8. Малые выборки и неопределённость показаны?
9. Выбросы на месте?
10. Читатель без подготовки поймёт график за 10 секунд?

Если хотя бы на один ответ «нет», исправь до выдачи.

## Как подавать это неспециалисту

Когда правило ограничивает пожелание пользователя, не отказывай молча. Объясни в одну-две фразы, почему, и сразу предложи ближайшую честную альтернативу.
Пример: «Круговая диаграмма плохо передаёт разницу между долями: глаз хуже сравнивает углы, чем длины. Сделал отсортированные столбцы, разница видна сразу».

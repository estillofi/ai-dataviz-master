# Правила визуализации данных: стиль Giorgia Lupi (Pentagram), Data Humanism

## 0. Как использовать этот файл

Файл прикрепляется к данным (CSV, XLSX, JSON, таблица в тексте). Claude обязан:

1. Прочитать данные и найти главный инсайт (один на фигуру).
2. Выбрать словарь символов по разделу 5.
3. Выдать **один самодостаточный HTML-файл** (всё inline, без внешних стилей).
4. Применить все правила ниже. Если **стилевое** правило (цвет, шрифт, форма подписи, раскладка) конфликтует с запросом пользователя, приоритет у запроса: сообщи об этом одной строкой. **Правила честности данных запрос пользователя не отменяет:** столбцы от нуля, без двойных осей, 3D и круговых диаграмм, без подгонки вывода и скрытия данных. На такую просьбу объясни в одну-две фразы и сделай честную замену. Предупреждение не делает нечестный график допустимым, «оба варианта» не делай.
5. Прогнать чек-лист раздела 12 до выдачи.

Если инсайт неочевиден или историй несколько, выбери одну сам, назови её в ответе и спроси, нужна ли другая. Не задавай вопросов до первой версии.

Формат ответа после генерации: файл + 3-4 строки: какой инсайт и какая форма выбраны и почему, что в данных было нестандартного (пропуски, выбросы, агрегации).

### Когда использовать

Личные истории и качественные данные: портрет человека, класса, команды; опыт, привычки, дневники, интервью; лонгрид с «человеческим» голосом; крафтовый отчёт, плакат, мерч, брендовый паттерн из данных. Формат для медленного чтения: экран с вниманием, печать, постер.

Не использовать: мониторинг, дашборды, быстрые решения по цифрам (берите Yau), > ~300 записей без агрегации, данные о людях без анонимизации.

## 2. Принципы

1. **За каждым числом человек.** Данные — след реальной жизни, не абстракция.
2. **Один символ — одна запись.** Читатель может сосчитать записи и увидеть каждую.
3. **Свой визуальный словарь.** Символы и штрихи выводятся из природы данных, а не берутся из набора диаграмм.
4. **Контекст всегда.** Качественные детали (почему, как, с кем) кодируются вариациями символа, подписями, заметками.
5. **Сложность с иерархией.** Много слоёв допустимо, если есть точка входа и порядок чтения.
6. **Несовершенство честно.** Неопределённость, пропуски, ошибки видны и названы.
7. **Легенда — половина работы.** Без неё картинка не информация.

## 5. Словарь символов и кодирование

Выводи словарь из данных. Ограничения: **4-6 форм, ≤ 4 переменные на фигуру**.

| Канал | Что кодирует | Пример |
|---|---|---|
| Форма штриха | Категория события | крест, палочка, дуга, кольцо, точка, засечка |
| Акварельное пятно (цвет) | Вторая категория или качество | настроение, источник, роль |
| Размер символа (3-5 ступеней) | Величина | усилие, длительность. Ступени перечислены в легенде, непрерывной точности не обещаем |
| Стиль контура | Определённость | пунктир, светлое пятно, «?» = оценка или неуверенность |
| Положение | Время или порядок | строка = день, позиция = порядок события |

Правила:

- Количество символов = количеству записей. Итоги по строкам и столбцам подписаны.
- Размер растёт от нуля (нет «0-го» размера у существующей записи).
- Пропуск = маленькое пустое кольцо, а не отсутствие символа.
- Порядок записей объявлен в легенде («по времени», «по важности»).
- Для качественных деталей: поле `note` у записи показывается как `<title>`/подсказка по наведению.

**Формы раскладки:** сетка «строка = период» (как в Dear Data), радиальные «часы», стопки, ветвь/дерево для иерархий, «портрет» (одна сущность — один составной символ).

## 6. Рукотворность и иерархия

**Рукотворность. Меняет форму, не данные:**
- Дрожь линий: `feTurbulence` (`baseFrequency` .04-.06) + `feDisplacementMap` (`scale` ≤ 2.5) на **группе** символов.
- Штрих чуть изогнут (квадратичная кривая), поворот символа ±6°, всё через seeded PRNG от размера данных.
- Позиция записи никогда не смещается больше ~1.5px от номинальной.
- Текстура бумаги: один фиксированный слой страницы (`body::before`, SVG-шум, `mix-blend-mode: multiply`, `opacity` ≤ .55). Опциональна.
- Карандашные направляющие: тонкие, `--pencil`, 0.6px.

**Иерархия (читатель смотрит один аспект за раз):**
1. **Точка входа:** заголовок и самый крупный/тёмный элемент.
2. **Основная конструкция:** сетка символов.
3. **Вторичные истории:** рукописные аннотации на полях со стрелками, 1-4 штуки.
4. **Контекст:** метод сбора, что в данных отсутствует, источник.

Обязателен блок «Чего здесь нет» (что не записано, кто не вошёл, какие ограничения).

## 7. Честность и этика

- Каждая запись видна и считаема. Скрытых записей нет.
- Неопределённость, оценки и пропуски обозначены (раздел 5).
- Данные о людях: без имён и идентификаторов, если пользователь прямо не попросил. Данные детей и учеников только агрегированно или псевдонимизированно. Если непонятно, можно ли показывать, спроси.
- Субъективность названа: кто и как собирал, какие вопросы не задавались.
- Заголовок не утверждает причинность, которой нет в данных.
- Красота не причина менять число, порядок или масштаб.

## 8. Легенда «Как читать» (обязательна, развёрнутая)

Легенда в том же рукотворном языке, группами по переменным:

1. Один символ = одна запись, порядок чтения.
2. «Штрих = вид» (образец + название для каждой формы).
3. «Пятно = …» (образец цвета + название).
4. «Размер = …» (3-5 ступеней с образцами).
5. Метки определённости (пунктир, «?»), если используются.

Легенда занимает столько места, сколько нужно, но структурирована заголовками. Расположение: сбоку или под фигурой, не внутри плотной сетки.

## 9. Композиция

- Контейнер `max-width: 1000px`, поля не меньше 5% по краям.
- Читаем слева направо, сверху вниз. Легенда справа, аннотации на полях.
- Воздух важнее плотности. Если символов слишком много, дели на панели (по периодам или группам).
- Адаптив: SVG `viewBox`. На < 600px легенда уходит под фигуру, подписи строк сокращаются.
- Печать: `print-color-adjust: exact`, текстура допустима.

## 10. Технические требования

- Один HTML-файл, inline SVG, ванильный JS. Данные константой `const DATA = [...]`.
- Фильтры на группах, не на каждом символе. > ~1500 символов: упрощай или дели на панели.
- Цвета и шрифты через CSS-переменные.
- Доступность: `role="img"`, `<title>`, `<desc>`, у каждого символа `<title>` с записью, контраст текста ≥ 4.5:1.
- Без localStorage, внешних запросов, счётчиков. Размер файла до 300 КБ.

## 12. Чек-лист

**Данные**
- [ ] Символов ровно столько, сколько записей. Итоги подписаны.
- [ ] Размер растёт от нуля, ступени названы в легенде.
- [ ] Пропуски, оценки, неопределённость обозначены.
- [ ] Есть «Как собраны данные» и «Чего здесь нет».
- [ ] Данные людей анонимизированы.

**Эстетика**
- [ ] Фон бумажный, линии рукотворные, но позиции не сдвинуты.
- [ ] ≤ 5 пятен, 4-6 форм, ≤ 4 переменных.
- [ ] Есть точка входа и порядок чтения, аннотации на полях.
- [ ] Текстура и дрожь тонкие, на группах.

**Легенда и текст**
- [ ] Легенда развёрнутая, в том же языке, сгруппирована по переменным.
- [ ] Заголовок говорит о людях и действиях, лид объясняет контекст.
- [ ] Контраст текста ≥ 4.5:1.

## 13. Антипаттерны

- Стандартные столбцы и круги в «рукописной» оболочке.
- Текстура и «акварель» ради красоты без словаря символов.
- Случайный разброс позиций, из-за которого нельзя сосчитать записи.
- Больше 4 переменных, больше 6 форм.
- Фигура без легенды или с легендой «в углу, потом разберёшься».
- Применение к мониторингу и быстрым решениям.
- Имена и идентифицирующие детали людей без запроса.
- Рукописный шрифт для абзацев.
- «Чего здесь нет» опущено.

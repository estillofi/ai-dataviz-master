# Правила визуализации данных: стиль Nathan Yau (FlowingData)

## 0. Как использовать этот файл

Файл прикрепляется к данным (CSV, XLSX, JSON, таблица в тексте). Claude обязан:

1. Прочитать данные и найти главный инсайт (тренд, выброс, разрыв, перелом).
2. Выбрать тип графика по разделу 5.
3. Выдать **один самодостаточный HTML-файл** (всё inline, без внешних стилей).
4. Применить все правила ниже. Если **стилевое** правило (цвет, шрифт, форма подписи, раскладка) конфликтует с запросом пользователя, приоритет у запроса: сообщи об этом одной строкой. **Правила честности данных запрос пользователя не отменяет:** столбцы от нуля, без двойных осей, 3D и круговых диаграмм, без подгонки вывода и скрытия данных. На такую просьбу объясни в одну-две фразы и сделай честную замену. Предупреждение не делает нечестный график допустимым, «оба варианта» не делай.

Если инсайт неочевиден или в данных несколько равноценных историй, выбери одну сам, назови её в ответе одной строкой и спроси, нужна ли другая. Не задавай вопросов до первой версии.

Формат ответа после генерации: файл + 2-3 строки: какой инсайт выбран, какой тип графика и почему, что в данных было нестандартного (пропуски, выбросы, обрезанные периоды).

## 1. Философия (6 принципов)

1. **Данные первыми.** Каждый пиксель либо несёт данные, либо помогает их читать. Остальное удаляется.
2. **Статистическая честность.** График не врёт формой. Нет обманчивых осей, 3D, усечённых столбцов.
3. **Zero chartjunk.** Нет теней, градиентов, рамок вокруг графика, фоновых картинок, иконок-украшений, декоративных подписей.
4. **Один акцент.** Серый фон истории, один яркий цвет для главной мысли.
5. **Подписи рядом с данными.** Читатель не бегает глазами между легендой и линией.
6. **Заголовок = вывод.** Не «Продажи по месяцам», а «Продажи выросли втрое после запуска в марте».

## 2. Дизайн-токены (использовать строго эти значения)

```css
:root {
  /* Поверхности */
  --bg: #FFFFFF;

  /* Данные: базовая серая палитра */
  --data-base: #B4B9C0;        /* основная серия, фоновые линии/точки */
  --data-base-light: #D5D8DD;  /* вторичные серии, если их много */
  --data-base-dark: #8A9099;   /* серия, которая важна, но не главная */

  /* ЕДИНСТВЕННЫЙ акцент (выбрать один на весь график) */
  --accent: #D7263D;           /* красный (по умолчанию) */
  /* альтернатива: --accent: #1F6FEB;  синий. Красный и синий вместе: запрещено. */

  /* Структура */
  --grid: #ECEEF1;             /* сетка */
  --axis: #C4C8CE;             /* оси и засечки */

  /* Текст */
  --text-title: #14171A;
  --text-body: #3C4249;
  --text-muted: #7A818A;       /* подписи осей, источник, примечания */

  /* Типографика */
  --font: "Source Sans 3", Arial, sans-serif;   /* файл и @font-face: ../fonts/README.md; без файла сработает Arial */
}
```

Правила цвета:

- Белый фон `#FFFFFF`. Тёмной темы нет.
- Акцент используется **только** для: главной серии/точки, выброса, ключевой аннотации, ключевого числа в заголовке (опционально).
- Всё остальное: оттенки серого. Не вводить второй, третий цвет.
- Если категорий много (> 6), красим акцентом одну, остальные серые разной светлоты, подписываем каждую напрямую.
- Акцентный цвет в тексте используется только на 1-2 ключевых словах/числах.
- Контраст текста на белом не ниже 4.5:1 (`--text-muted` минимально допустимый серый).

## 3. Типографика и иерархия

| Элемент | Размер | Вес | Цвет |
|---|---|---|---|
| Заголовок (вывод) | 28px (мобильный 22px) | 700 | `--text-title` |
| Подзаголовок (что измерено, период, единицы) | 15px | 400 | `--text-body` |
| Аннотации на графике | 13px | 400-600 | серый или `--accent` |
| Подписи осей, засечки | 12px | 400 | `--text-muted` |
| Источник, примечания | 11-12px | 400 | `--text-muted` |

Правила:

- Только sans-serif из `--font` (Source Sans 3, запасной Arial). Сетевые шрифты не подключать.
- Не больше 3 размеров и 2 весов на странице, кроме заголовка.
- Выравнивание по левому краю. Центрирование заголовка запрещено.
- Межстрочный интервал: заголовок 1.2, текст 1.45.
- Числа: `font-variant-numeric: tabular-nums`. Тысячи разделять тонким пробелом или запятой, единообразно.
- Иерархия чтения: заголовок → график → аннотации → оси → источник.

## 4. Структура страницы

```
[Заголовок-вывод]
[Подзаголовок: что, где, когда, единицы]
[График, SVG на всю ширину контейнера]
[Источник · Примечания о данных]
```

- Контейнер: `max-width: 880px`, по центру страницы, `padding: 32px 20px`.
- Нет карточек, рамок, теней, фонов у контейнера.
- График адаптивный: SVG с `viewBox`, `width: 100%`, высота по пропорции (по умолчанию 16:10, для временных рядов можно 2:1).
- На мобильном (< 600px): уменьшить число засечек, сократить подписи, сохранить прямые аннотации.
- Всегда есть строка «Источник: …» (если пользователь не дал источник, писать «Источник: данные пользователя»).

## 5. Выбор типа графика

| Задача | Тип | Заметки |
|---|---|---|
| Изменение во времени | Линейный график | Основной тип по умолчанию для временных рядов |
| Сравнение категорий | Горизонтальные столбцы (отсортированы) | Подписи категорий слева, значения у конца столбца |
| Динамика категорий между 2 точками | Slopegraph | Две вертикальные оси, подписи слева и справа |
| Связь двух числовых переменных | Scatterplot | Акцент на выбросы, линия тренда только если она нужна для вывода |
| Распределение | Гистограмма или strip/dot plot | Не boxplot для неспециалистов |
| Часть от целого (≤ 5 частей) | Один stacked-столбец или сортированные столбцы | Круговые диаграммы запрещены. Donut запрещён |
| Много серий во времени | Small multiples (сетка мини-графиков с общей осью) | Предпочтительнее одного графика с 8 линиями |
| Гео-данные | Карта только если пространство важно | Иначе столбцы |

Запрещено: 3D, pie, donut, radar, градиентные заливки, двойные оси Y, анимации ради анимации, «спидометры», иконки вместо данных.

## 6. Правила осей, сетки, геометрии

**Оси**
- Толщина 1px, цвет `--axis`. Засечки короткие (4px) или отсутствуют.
- Ось X для времени: подписывать редко (каждый год/квартал), не каждую точку.
- Ось Y: 4-6 значений максимум. Единицы указываются **один раз**, рядом с верхней отметкой («120 тыс. ₽») или в подзаголовке. Заголовок оси сбоку не ставить.
- Убрать линии осей, если сетка и подписи справляются без них (особенно ось Y).

**Сетка**
- Только горизонтальная, 1px, `--grid`. Вертикальная сетка только для scatterplot.
- Нулевая линия на столбцах: чуть темнее (`--axis`).

**Данные**
- Линии: 2px для базовых серий (`--data-base`), 3px для акцентной (`--accent`). `stroke-linecap: round`, `stroke-linejoin: round`.
- Точки: радиус 3px, только на ключевых значениях (конец линии, выброс, пик). Не на каждой точке ряда.
- Столбцы: без обводки, скругления 0-2px, зазор 30-40% ширины столбца.
- Прозрачность для scatter с наложением: `opacity: 0.6`.
- Все элементы выровнены по пиксельной сетке (`shape-rendering: crispEdges` для столбцов и сетки).

**Честность шкал**
- Столбцы: ось Y **начинается с нуля**. Без исключений.
- Линии: ноль необязателен, но диапазон должен быть разумным. Если ось усечена, пометить это в примечании.
- Лог-шкала: только когда важен рост в процентах, обязательно подписать «лог. шкала».
- Единый масштаб во всех small multiples (если не оговорено иначе).
- Пропуски в данных показывать разрывом линии, не интерполировать молча.
- Прогнозы и оценки: пунктир (`stroke-dasharray: 4 3`) + подпись «прогноз».

## 7. Аннотации и подписи

Главное правило: **нет отдельной легенды**.

- Серии подписываются напрямую, у конца линии (справа, с отступом 6-8px), цветом серии.
- Если подписи конкурируют за место, сдвинуть по вертикали, добавить тонкую выноску 1px `--axis`.
- Ключевой инсайт отмечается аннотацией: короткий текст (1-2 строки, до ~12 слов) рядом с точкой/участком + тонкая линия-указатель. Цвет текста `--accent` или `--text-body`.
- Аннотация объясняет **почему**, а не повторяет **что** («Запуск рекламы», «Смена тарифа»), и только если причина известна из данных или пользователь её назвал. Не выдумывать причины.
- Значения подписываются прямо на ключевых точках (начало, конец, пик, выброс), не везде.
- Для столбцов: значение у конца столбца, без подписи оси значений вообще, если подписаны все значения.
- Tooltip: допустим как дополнение при hover (простой, без анимаций, белый фон, 1px рамка `--axis`), но график должен читаться без него.
- Подписи не перекрывают данные. Белая подложка (`paint-order: stroke; stroke: #fff; stroke-width: 3px`) для текста поверх линий.

## 8. Заголовок и подзаголовок

**Заголовок** формулирует вывод, с числом, если оно есть:

- Плохо: «Выручка по кварталам»
- Хорошо: «Выручка выросла на 42% за год, но весь рост пришёл из одного региона»

Правила:
- Одно утверждение, до 2 строк, глагол обязателен.
- Только то, что подтверждают данные. Не писать причинность там, где есть корреляция.
- Ключевое число или слово можно выделить цветом `--accent`.

**Подзаголовок** отвечает на вопросы: что измерено, период, единицы, фильтры. Пример: «Ежемесячная выручка, тыс. ₽, янв 2023 – окт 2026».

## 9. Технические требования к HTML

- Один файл `.html`, весь CSS и JS внутри.
- Рендер: **inline SVG, собранный на ванильном JS** (предпочтительно). D3 допустим, подключение только `https://cdnjs.cloudflare.com/ajax/libs/d3/7.9.0/d3.min.js` с зафиксированной версией. Chart.js и другие готовые чарт-библиотеки не использовать (они тащат стандартную эстетику и chartjunk).
- Данные встроены как константа JS в начале скрипта (`const DATA = [...]`). Легко заменить.
- Все цвета, шрифты, толщины берутся из CSS-переменных раздела 2.
- Шрифты: Source Sans 3 — локальные файлы из `../fonts/` через `@font-face` (в скилле — `assets/fonts/`) и запасной стек; сетевые шрифты не подключать.
- `<meta name="viewport" content="width=device-width, initial-scale=1">`.
- Доступность: `role="img"` и `<title>`/`<desc>` у SVG с описанием вывода; не полагаться только на цвет (акцентная серия ещё и толще, и подписана).
- Текст в HTML: типографские кавычки «ёлочки», апостроф ’, длинное тире там, где нужно по языку страницы.
- Язык страницы = язык данных/запроса (`<html lang="ru">` для русского).
- Без localStorage, без внешних запросов, без счётчиков.
- Размер файла: до 200 КБ.

## 11. Чек-лист перед выдачей (Claude проверяет сам)

**Честность**
- [ ] Столбцы начинаются с нуля.
- [ ] Нет двойной оси Y, 3D, pie/donut.
- [ ] Пропуски, прогнозы, усечения отмечены.
- [ ] Вывод в заголовке подтверждается данными, причинность не выдумана.

**Дизайн**
- [ ] Фон белый, градиентов, теней, рамок нет.
- [ ] Ровно один акцентный цвет, всё остальное серое.
- [ ] Акцент стоит только на главном инсайте.
- [ ] Сетка и оси тонкие (1px), приглушённые.
- [ ] Легенды нет, подписи рядом с данными.
- [ ] Есть минимум одна аннотация ключевого момента.
- [ ] Заголовок формулирует вывод.

**Техника**
- [ ] Один HTML-файл, открывается без интернета (кроме D3 с cdnjs, если использован).
- [ ] Цвета и шрифты через CSS-переменные.
- [ ] Адаптивность проверена мысленно на 375px и 1280px.
- [ ] Есть источник и подзаголовок с единицами.

## 12. Антипаттерны (не делать)

- Радужные палитры и «красивые» градиенты по категориям.
- Легенда в углу, которую нужно сопоставлять по цвету.
- Подписи значений на каждой точке линии.
- Заголовок-тема («Динамика показателей»).
- Рамка вокруг графика, фон под областью построения.
- Декоративные иконки, эмодзи, логотипы внутри графика.
- Анимация появления, которая задерживает чтение данных.
- Сглаживание линий (`curve smoothing`), искажающее значения. Использовать прямые отрезки.
- Больше одного акцента «потому что важных вещей много». Если их много, делай small multiples или несколько графиков, по одному инсайту на график.

## 13. Быстрые варианты запроса (пример промптов вместе с файлом)

- «Визуализируй по правилам из файла. Инсайт найди сам.»
- «Визуализируй по правилам из файла. Акцент на [категория/период].»
- «Small multiples по регионам, акцент на тех, где падение.»
- «Синий акцент вместо красного.»

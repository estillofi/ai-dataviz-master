# Правила визуализации данных: стиль Federica Fragapane (органическое data-art)

## 0. Как использовать этот файл

Файл прикрепляется к данным (CSV, XLSX, JSON, таблица в тексте). Claude обязан:

1. Прочитать данные: сколько сущностей, какие переменные, есть ли время, иерархия, связи.
2. Выбрать **метафору формы** по разделу 4 (цветок, раковина-спираль, волна, созвездие, ветвь).
3. Назначить каждой переменной **визуальный канал** по разделу 5 и нарисовать обязательный ключ «Как читать».
4. Выдать **один самодостаточный HTML-файл** с inline SVG.
5. Прогнать чек-лист раздела 12.

Формат ответа после генерации: файл + 3-4 строки: какая метафора выбрана и почему, какая переменная в каком канале закодирована, что в данных нестандартного (пропуски, выбросы, агрегации).

Если данных слишком мало (< 4 значений) или слишком много (> 60 сущностей в одной фигуре), скажи об этом и предложи агрегацию или small multiples (несколько малых фигур с общей шкалой).

## 1. Философия (6 принципов)

1. **Форма — это данные.** Каждый лепесток, виток, изгиб или узел привязан к значению. Декор без привязки к данным запрещён.
2. **Красота служит чтению.** Изящество не оправдывает нечитаемость. Если зритель не может восстановить значение по ключу, фигура провалена.
3. **Много слоёв, один порядок.** Сложность допустима, хаос нет. Структура строится из нескольких слоёв с чёткой иерархией (раздел 7).
4. **Тонкость.** Нити, микроскопические точки, пунктирные направляющие. Толстых линий почти нет.
5. **Тишина текста.** Минимум слов, максимум пространства. Фигура рассказывает, текст только направляет.
6. **Воспроизводимость.** Одни и те же данные дают ту же картинку (детерминированный seed).

**Тест на декор:** удали из фигуры все элементы, не привязанные к данным. Если ничего не изменилось в чтении, они были лишними. Исключение: структурные направляющие (кольца, оси, пунктиры), см. раздел 7.

## 2. Дизайн-токены (использовать строго эти значения)

```css
:root {
  /* Поверхность */
  --bg: #F8F5EF;            /* тёплый off-white, сплошной, без текстуры */

  /* Палитра данных (приглушённая) */
  --pink: #D9A9AB;          /* dusty pink */
  --pink-deep: #BC7C85;
  --sage: #A8B89E;          /* sage green */
  --sage-deep: #7F967B;
  --cream: #EBDFC6;         /* soft cream */
  --plum: #4A2545;          /* deep plum: контур, текст, главный тёмный */
  --plum-soft: #86628A;

  /* Линии и текст */
  --line: rgba(74, 37, 69, 0.35);   /* филигрань */
  --line-faint: rgba(74, 37, 69, 0.18); /* направляющие, кольца */
  --text-title: #3A1B38;
  --text-body: #5B4059;
  --text-muted: #8B7589;

  /* Шрифты */
  --font-display: "Literata", Georgia, serif;   /* файлы и @font-face: ../fonts/README.md */
  --font-ui: "Manrope", Arial, sans-serif;
}
```

Правила цвета:

- Фон: сплошной `--bg`. Никаких рамок, виньеток, текстур, тёмных панелей.
- Используем 4 семейства: pink, sage, cream, plum. Больше цветов не вводить. Оттенки внутри семейства (`-deep`, `-soft`) допустимы.
- **Категориальная переменная**: одна категория = одно семейство (pink / sage / cream). Plum закреплён за контуром, текстом и самым важным элементом.
- **Количественная переменная**: через светлоту одного семейства (светлый → тёмный), не через смену оттенков.
- **Градиенты**: минимально. Допустим 2-стопный градиент внутри одного семейства, разница светлоты ≤ 15%. Только в заливках лепестков/раковин, не в фоне, не в линиях.
- **Прозрачность заливок**: 0.55-0.85. При наложении фигур использовать `mix-blend-mode: multiply`, чтобы пересечения читались.
- **Контраст текста**: текст всегда `--plum`, `--text-body` или `--text-muted` (не pink и не sage: на off-white они не проходят 4.5:1).

## 4. Метафоры формы (выбор по структуре данных)

| Структура данных | Метафора | Геометрия |
|---|---|---|
| Категории с одним-двумя числами (5-40 шт.) | **Цветок** | Лепестки расходятся от центра по кругу. Угол = категория, длина = значение |
| Временной ряд, цикличность, сезонность | **Спираль / раковина** | Угол = период цикла (месяц, час), радиус растёт с порядковым номером (год, виток) |
| Временной ряд, несколько серий | **Волны** | Параллельные плавные линии, амплитуда = значение, сдвиг по вертикали = серия |
| Связи, сети, корреляции, потоки между сущностями | **Созвездие** | Узлы-точки и тонкие дуги. Размер узла = значение, дуга = связь |
| Иерархия (категория → подкатегория → элемент) | **Ботаническая ветвь** | Ствол = корень, ветви = уровни, листья = элементы |
| Сравнение групп по нескольким метрикам | **Цветочные соцветия** (small multiples) | Один маленький цветок на группу, общая шкала |

Правила:

- Выбирай **одну** главную метафору. Вторую допустимо добавить только как вспомогательную (например, малая спираль в углу).
- Форма должна быть **осмысленна**: цикличные данные в спираль/круг, линейные в волны, связи в созвездие. Не ради красоты.
- Если метафора ломает точность чтения (например, много близких значений на лепестках), увеличь радиус, добавь кольцо-шкалу или переключись на волны.

## 5. Кодирование данных: что куда

Каждая переменная получает **один** канал. Точность каналов по убыванию:

1. Положение вдоль радиуса или оси (длина лепестка, радиус витка, высота волны)
2. Угол / порядок по кругу
3. Размер точки или узла (площадь, не радиус: `r = k * sqrt(value)`)
4. Светлота цвета
5. Оттенок (только для категорий)
6. Плотность / число элементов (микроточек, нитей)

Правила:

- **Главную количественную переменную кодируй длиной или положением** (каналы 1-2). Не цветом и не размером.
- Длина лепестка **пропорциональна значению от нуля**. Ширина лепестка постоянна (иначе читатель считает площадь и ошибается). Если ширина кодирует вторую переменную, это объявляется в ключе.
- Размер точек пропорционален **площади**.
- Не больше **4 переменных** на фигуру. Лучше 2-3.
- Минимальная видимая длина/размер: 6px. Нулевые и пропущенные значения показываются пустым маркером (маленькое кольцо), а не отсутствием элемента.
- Порядок лепестков/узлов: осмысленный (по убыванию, по времени, по группе). Не случайный.
- Прогнозы и оценки: контур пунктиром, заливка светлее, подпись «оценка».
- Шкала: кольца-направляющие на круглых формах (3-4 кольца, пунктир `1 4`, подписи значений на одном радиусе).

## 6. Геометрия и линии

**Толщины:**

| Элемент | Толщина |
|---|---|
| Филигрань (контуры, нити) | 0.4-0.8px |
| Направляющие пунктиры | 0.5px, `stroke-dasharray: 1 4` или `2 4` |
| Контуры главных форм | 0.75-1.25px |
| Микроточки (декор шкалы) | r 0.6-1.2px |
| Точки данных | r 1.5-6px |

Максимум 1.25px для любой линии, кроме одной «героической» линии (до 2px), если нужна.

**Формы:**

- Лепестки: симметричная капля на кубических кривых Безье, острая вершина или мягкое закругление, постоянная ширина.
- Спирали: Архимедова (`r = r0 + b·θ`) для равномерных витков.
- Волны: плавные кривые (Catmull-Rom → Безье). Здесь сглаживание **допустимо**, это органика. Но узловые точки данных отмечай микроточками, чтобы читатель видел реальные значения.
- Дуги связей: кривые Безье, изгиб к центру, прозрачность 0.4-0.6.
- Все элементы математически выверены. Никаких «рисованных от руки» неровностей.

**Детерминизм:**

- Любая «случайность» (микроточки, лёгкий разброс) идёт через seeded PRNG (`mulberry32`), seed считается от данных. Разброс не должен смещать значение: допускается только в декоративных микроточках, не в позициях данных.

## 7. Слои (порядок отрисовки, снизу вверх)

1. **Фон** `--bg`.
2. **Структурные направляющие**: кольца-шкала, оси, радиальные пунктиры. `--line-faint`.
3. **Связующие нити**: тонкие пунктиры и дуги между элементами (`--line`).
4. **Заливки форм**: лепестки, витки, ленты. Прозрачность 0.55-0.85.
5. **Контуры форм**: `--plum` 0.75px или `--line`.
6. **Микроточки и точки данных**.
7. **Подписи и значения**.
8. **Ключ «Как читать»** (вне основной фигуры).

Правила слоёв:

- Каждый слой группируется в `<g id="layer-...">`.
- Структурные направляющие допустимы как «неинформационные» элементы. Всё остальное привязано к данным.
- Плотность: чем дальше от центра внимания, тем слабее слой (меньше opacity).

## 8. Композиция страницы

```
[Заголовок]
[Лид, ≤ 40 слов]
[Основная фигура: большая, с воздухом]
[Ключ «Как читать»: рядом с фигурой или в углу]
[Источник · Примечания]
```

- Контейнер: `max-width: 1100px`, по центру, `padding: 48px 24px`.
- Отношение сторон основной фигуры: квадрат или 4:3 для круглых форм, 16:10 для волн.
- Свободного места вокруг фигуры не меньше 8% её ширины. Воздух — часть стиля.
- Выравнивание текста по левому краю, фигура по центру.
- Адаптив: SVG `viewBox` + `width: 100%`. На < 600px убрать вторичные подписи, оставить заголовок, фигуру и ключ под ней.
- Печать: `@media print` сохраняет цвета (`print-color-adjust: exact`).

## 9. Ключ «Как читать» (обязателен)

Нестандартные формы требуют объяснения. В отличие от классической диаграммы, здесь легенда нужна. Но она должна быть **изящной и компактной**.

Состав:

- Мини-версия **одного** элемента (один лепесток, один виток, один узел) с стрелками-выносками на тонких линиях.
- Подписи выносок: «длина = значение», «цвет = регион», «угол = месяц».
- Две-три опорные величины для шкалы (например, лепестки длиной 10, 50, 100 рядом).
- Не более 5 строк текста.

Расположение: правый нижний угол или под фигурой. Тот же стиль линий, что и в основной фигуре.

## 10. Статистическая честность

- Длина/положение от нуля, пропорционально значению. Никаких «красивых» усечений.
- Площадь не искажается: размер точки через `sqrt`.
- Сортировка не должна создавать ложных паттернов; если порядок произвольный, скажи это в примечании.
- Выбросы не «подрезаются» ради композиции. Если один лепесток в 10 раз длиннее остальных, дай ему выйти за кольца или используй объявленный разрыв шкалы (с подписью).
- Пропуски показываются, не интерполируются.
- Агрегации и сглаживание объявляются в примечании.
- Подпись источника обязательна. Если пользователь не дал источник: «Источник: данные пользователя».
- Не добавляй в заголовок причинность, которой нет в данных.
- Красота не причина менять данные, масштаб или порядок.

## 11. Технические требования к HTML

- Один файл `.html`, CSS и JS внутри.
- Рендер: **inline SVG, генерируемый ванильным JS**. Внешние библиотеки не нужны. Если очень нужны шкалы или layout, допускается D3 только с `https://cdnjs.cloudflare.com/ajax/libs/d3/7.9.0/d3.min.js` (версия зафиксирована).
- Данные встроены константой `const DATA = [...]` в начале скрипта.
- Все цвета и шрифты через CSS-переменные раздела 2.
- Шрифты: Literata + Manrope — локальные файлы из `../fonts/` через `@font-face` (в скилле — `assets/fonts/`) и запасной стек; сетевые шрифты не подключать.
- `<meta name="viewport" content="width=device-width, initial-scale=1">`.
- Hover: подсвечивать элемент (opacity других 0.25) и показывать значение рядом. Без всплывающих окон с тенью. Фигура читается и без hover.
- Анимация: по умолчанию нет. Допустим один мягкий fade-in (≤ 600 мс), отключаемый через `prefers-reduced-motion`.
- Доступность: `role="img"`, `<title>`, `<desc>` с текстовым выводом; не полагаться только на цвет (категория дублируется подписью).
- Типографика текста: «ёлочки», ’, длинное тире.
- `<html lang>` соответствует языку данных/запроса.
- Без localStorage, внешних запросов, счётчиков. Размер файла до 300 КБ.

## 13. Антипаттерны

- Цветы ради цветов: лепестки одинаковой длины, ничего не кодирующие.
- Радужные или неоновые палитры, насыщенный фиолетовый и зелёный «как в генераторах».
- Тяжёлые тени, свечение, 3D, глянец.
- Градиентный фон, виньетки, текстуры бумаги.
- Площадь лепестка как носитель значения при переменной ширине без объявления.
- Подписи розовым или салатовым по белому (нечитаемо).
- Абзацы текста внутри фигуры.
- Случайный порядок элементов, создающий ложные паттерны.
- Сглаживание, скрывающее реальные точки данных.
- Нагромождение: 100+ сущностей в одной фигуре без агрегации.
- Фигура без ключа «Как читать».

function rng(seed) {
  return () => {
    seed |= 0; seed = seed + 0x6D2B79F5 | 0;

function petalPath(cx, cy, a, r0, len, w) {
  const dx = Math.cos(a), dy = Math.sin(a), nx = -dy, ny = dx;
  const bx = cx + dx * r0, by = cy + dy * r0;
  const P = (t, s) => [bx + dx * len * t + nx * w * s, by + dy * len * t + ny * w * s];
  const c1l = P(.30, 1), c2l = P(.80, .55), tip = P(1, 0), c2r = P(.80, -.55), c1r = P(.30, -1);

// плавная кривая через точки (Catmull-Rom → Безье) для волн
function smooth(pts) {
  let d = `M${pts[0]}`;
  for (let i = 0; i < pts.length - 1; i++) {
    const p0 = pts[i - 1] || pts[i], p1 = pts[i], p2 = pts[i + 1], p3 = pts[i + 2] || p2;
    d += `C${[p1[0] + (p2[0] - p0[0]) / 6, p1[1] + (p2[1] - p0[1]) / 6]} ` +
         `${[p2[0] - (p3[0] - p1[0]) / 6, p2[1] - (p3[1] - p1[1]) / 6]} ${p2}`;
  }
  return d;
}

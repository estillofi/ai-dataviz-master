# Гайд по сборке: как наколдовать своего AI-DataViz мастера

Через час у вас будет навык, который при просьбе «сделай график», «собери дашборд» или «добавь данные в презентацию» отвечает **в стиле вашей команды**, **по строгим правилам честной визуализации** и **одинаково каждый раз**.

Нужны: компьютер, чат с нейросетью (лучше агент с доступом к папке), цвета и шрифты вашего бренда (если есть) и пример данных.

## 1. Принцип: обычные вещи, пока они работают

Этот набор намеренно скучный:

- Всё это **текстовые файлы** (Markdown) и несколько маленьких скриптов на стандартной библиотеке Python. Нет фреймворков, баз данных, серверов, ключей API.
- Результат это **папка со `SKILL.md`**: открытый формат Agent Skills, он читается Claude, Codex и другими агентами.
- Один график = один HTML-файл без внешних зависимостей. Его можно открыть двойным щелчком.
- Правила честности написаны словами и проверяются **инструментом там, где это возможно** (контраст, дальтонизм, структура скилла).

**Правило сборки:** пока простая вещь работает, не усложняйте. Сложное добавляйте только после того, как простое сломалось, и записывайте в журнал: что сломалось, что добавили, почему.

Лестница от простого к сложному:

| Шаг | Что делаете | Усложняйте, только если |
|---|---|---|
| 1 | Вставили `single-file-prompt.md` в обычный чат | Чат не держит такой объём |
| 2 | Открыли папку набора в агенте с доступом к файлам | Нужны проверки кодом и скриншоты |
| 3 | Установили готовый скилл в агента | Скилл не подключается по описанию |
| 4 | Положили скилл в общий приватный репозиторий команды | Нужна совместная работа |

Если на шаге 1 всё работает, остальное не нужно.

## 2. Выберите уровень входа

| Уровень | Что нужно | Подходит | Результат |
|---|---|---|---|
| **L0. Обычный чат** | Любой чат с нейросетью, умеющий читать длинный текст | ChatGPT, Gemini, Claude.ai, любой другой | Файлы скилла в виде блоков кода: вы сохраняете их сами |
| **L1. Агент с папкой** | Агент, который читает и пишет файлы в папке | Claude Cowork, Claude Code, Codex CLI, Cursor и подобные | Готовая папка скилла, проверки кодом, тестовая галерея |
| **L2. С установкой** | L1 + установка скилла | Те же | Скилл подключается сам при запросах на графики |

Рекомендация: начните с **L1**. L0 годится, если файлового агента нет.

## 3. Подготовка за 15 минут

Соберите (можно не всё, агент предложит безопасные значения):

| Что | Зачем | Если нет |
|---|---|---|
| Цвета бренда (HEX, фото брендбука) | Основа палитры данных | Нейтральная палитра |
| Шрифты (названия, лицензия) | Заголовки и подписи | Системный шрифт |
| Логотип (SVG или PNG) | Шапка слайдов и дашбордов | Без логотипа |
| Шаблон презентации (.pptx, .potx) | Размеры и поля слайдов | Чистый 16:9 |
| 2-3 графика, которые нравятся; 1-2, которые нет | Показать ваш вкус | Агент предложит варианты |
| Пример данных **без персональной информации** | Проверка на реальных случаях | Тестовые данные |
| 3-5 реальных задач на ближайшие недели | Чтобы скилл решал ваши задачи | Агент спросит |

**Не присылайте:** пароли, ключи, токены, реальные персональные данные, файлы под NDA.

## 4. Установка набора

### 4.1. Получите набор

```bash
git clone https://github.com/estillofi/ai-dataviz-master.git
cd ai-dataviz-master
```

Или скачайте ZIP со страницы репозитория и распакуйте.

### 4.2. Сделайте рабочую копию (важно)

В процессе вы положите в папку логотипы, палитру, данные. **Эти материалы не должны попасть в публичный репозиторий.** Работайте в копии вне git:

```bash
cp -r ai-dataviz-master ~/dataviz-master-work
cd ~/dataviz-master-work
rm -rf .git
```

В набор включён `.gitignore`: он защищает от случайной отправки `01-brand-inputs/assets/`, `04-output/`, `05-research-log/` и `00-session/state.md`. Но надёжнее работать в копии.

### 4.3. Проверьте, что набор цел

Нужен Python 3.9 или новее (внешние пакеты не требуются):

```bash
python3 tests/lint_kit.py
python3 -m unittest discover -s tests -p "test_*.py"
```

Ожидаемо: `lint: ошибок 0` и `OK`. Если красное, дальше не идите: сначала раздел 11.

## 5. Запуск по платформам

### A. Claude (Cowork или Claude Code)

1. Откройте приложение **в папке набора** (Cowork: выбрать папку; Claude Code: `cd ~/dataviz-master-work && claude`).
2. Вставьте первую фразу:

   ```
   Прочитай AGENTS.md в этой папке и начни онбординг. Веди меня по этапам, задавай вопросы небольшими порциями. Файлы буду класть в 01-brand-inputs или присылать в чат.
   ```
3. Отвечайте на вопросы. Если чего-то не знаете, так и скажите.
4. Если сеанс оборвался: откройте новый чат в той же папке и напишите: «Продолжи онбординг по 00-session/state.md».

### B. Codex CLI

Установка (нужен Node.js 18+; на Windows поддержка экспериментальная):

```bash
npm install -g @openai/codex
cd ~/dataviz-master-work
codex
```

Codex автоматически читает `AGENTS.md` в рабочей папке. Первая фраза:

```
Выполни онбординг по AGENTS.md. Задавай вопросы небольшими порциями с вариантами ответов. Файлы я положу в 01-brand-inputs.
```

Неинтерактивный режим (`codex exec "..."`) подходит для тестов с заранее написанными ответами (см. `tests/`), но для живого интервью используйте интерактивный.

### C. Обычный чат без файлов (L0)

1. Соберите один файл:

   ```bash
   python3 tools/bundle_single_file.py
   ```

   Получится `dist/single-file-prompt.md` с инструкцией, ядром правил, шаблонами, анкетой и двумя рекомендованными стилями (Yau и редакционным). Остальное: `--styles all` (все пять, длиннее), `--styles yau,lupi` (выбранные), `--styles none` (без файлов стилей). В начале документа перечислено, чего в нём нет, и агент обязан сказать вам об этом, а не делать вид, что файл у него есть.
2. Прикрепите файл к чату (или вставьте текстом, если чат принимает длинные сообщения) и напишите:

   ```
   Выполни этот документ. Ты в режиме «только чат». Начни с этапа 0.
   ```
3. Агент будет выдавать каждый файл блоком кода с путём. Сохраняйте их в папку `<название>-dataviz/` по указанным путям.
4. Для проверки запустите скрипты локально: `python3 tools/validate_skill.py <папка>`.

Если чат не принимает такой объём, выберите меньше стилей или разделите: сначала `AGENTS.md` и ядро, потом по запросу остальное.

### D. Другие агенты

Любой агент, который читает `AGENTS.md` или умеет «прочитать файл в папке», работает как L1. Формат результата (`SKILL.md` с `name` и `description`) открытый: проверьте в документации вашего агента, куда класть скилл.

## 6. Что происходит по этапам

| Этап | Время | Что делает агент | Что делаете вы |
|---|---|---|---|
| 0. Подготовка | 2 мин | Читает файлы, проверяет инструменты, объясняет план | Называете язык |
| 1. Контекст | 5 мин | Спрашивает про команду, аудиторию, задачи, данные | Отвечаете, называете 3-5 реальных задач |
| 2. Бренд | 5-10 мин | Разбирает ваши материалы, спрашивает недостающее | Присылаете цвета, шрифты, логотип |
| 3. Дегустация стилей | 5-10 мин | Показывает демо пяти стилей в ваших цветах | Выбираете основной стиль и потолок сложности |
| 4. Правила и каталог | 5 мин | Показывает правила честности, каталог графиков, глоссарий | Подтверждаете, дополняете метрики |
| 5. Дашборды | 3-5 мин | Спрашивает метрики и фильтры | Называете 3-5 метрик |
| 6. Презентации | 3 мин | Спрашивает программу и шаблон | Присылаете шаблон или называете программу |
| 7. Ресёрч | 5 мин | Ищет (с вашего разрешения), пишет журнал | Решаете до трёх вопросов |
| 8. Сборка | 10 мин | Строит палитру, проверяет инструментом, собирает файлы скилла | Утверждаете палитру |
| 9. Проверка | 10 мин | Тестовая галерея, тесты, упаковка, инструкция | Смотрите примеры, говорите «нравится / поправить» |

Время ориентировочное, не измерено: зависит от того, сколько материалов у вас готово и сколько вы хотите решать. Можно разбить на несколько сессий.

### Быстрый режим

Если нет времени или материалов, скажите агенту: «Быстрый режим». Он задаст три вопроса про команду, читателя и ближайшую задачу, возьмёт нейтральную палитру и основной стиль Yau или редакционный, соберёт скилл с минимальными проверками и честно перечислит, что осталось `TBD` (`AGENTS.md`, раздел 10). Потом можно вернуться и пройти этапы подробно.

## 7. Как отвечать, чтобы вышло хорошо

1. **«Не знаю» нормально.** Агент подставит безопасное значение и пометит его `TBD`. Вернётесь позже.
2. **Присылайте реальные примеры данных** (без персональной информации). Скилл проверяется на них.
3. **Решайте по примерам, а не по названиям.** На этапе 3 смотрите демо.
4. **Рекомендуемый потолок сложности: только простые формы.** Их понимают без объяснений, и результат предсказуем. Сложные формы можно добавить точечно.
5. **Не соглашайтесь на то, чего не понимаете.** Спросите «почему». Агент обязан объяснить в одну-две фразы.
6. **Если просите нечестное** (обрезать ось, круговую диаграмму), агент объяснит и предложит замену. Это не баг.
7. **Бренд-цвет ≠ цвет данных.** Агент может предложить чуть другой оттенок для данных, потому что оригинал плохо читается. Он покажет пару «было → стало» и цифры.
8. **Не присылайте секреты.** Если прислали, агент их не использует. Отзовите их.

## 8. Проверка результата

Не доверяйте на слово: проверьте шестью простыми способами.

### 8.0. Шлюз честности (обязательно)

```bash
python3 tools/check_honesty.py 04-output/test-gallery/*.html
```

Это обязательная проверка **перед** показом или отправкой любого HTML. ERROR означает почти наверняка нарушение (pie/donut, 3D, двойная ось, столбцы с осью не от нуля): результат выдавать нельзя, исправьте и запустите снова. Отсутствие ERROR не доказывает честность: тест из 10 вопросов из `02-references/core-rules/01-integrity-and-perception.md` всё равно обязателен. Нечестный график «с предупреждением» недопустим.

### 8.1. Структура скилла

```bash
python3 tools/validate_skill.py --strict 04-output/<название>-dataviz
```

Ожидаемо: `ошибок 0, предупреждений 0`. Строгий режим превращает предупреждения (пустые эталоны, скелет-заглушка, нет тестов) в ошибки. **Важно:** валидатор проверяет структуру и наличие файлов, а не качество содержимого. Качество подтверждают галерея, тесты и ваше одобрение.

### 8.2. Палитра

```bash
python3 tools/palette_audit.py --bg "#FFFFFF" \
  --text "#1F2933" "#52606D" \
  --graphics "#0072B2" "#D55E00" \
  --categorical "#0072B2" "#E69F00" "#009E73" "#CC79A7"
```

Смотрите: контраст текста ≥ 4.5:1, графики ≥ 3:1, пары цветов, которые путаются при дальтонизме. Предупреждения решает человек.

### 8.3. Глазами

Откройте 3-5 HTML из `04-output/test-gallery/`. Ответьте себе:

- Понятно ли за 10 секунд, что показывает заголовок?
- Столбцы начинаются с нуля?
- Есть источник и дата данных?
- Выглядит ли это «как мы»?

### 8.4. Тест подключения (после установки, **новый чат**)

Шесть формулировок, скилл должен подключаться во всех:

1. «Нарисуй график по этим данным»
2. «Сделай диаграмму продаж»
3. «Нужен дашборд»
4. «Сделай слайд с цифрами»
5. «Покажи на графике»
6. «Подготовь презентацию по итогам квартала» (с данными)

### 8.5. Токены, повторяемость, малые группы

```bash
# цвета и шрифты результата только из токенов
python3 tools/check_tokens.py результат.html <скилл>/assets/tokens.css

# два НЕЗАВИСИМЫХ запроса на одних данных после нормализации
python3 tools/compare_outputs.py а.html б.html --show-diff

# малые группы: одной пометки мало, скрытое не должно восстанавливаться вычитанием
python3 tools/suppress_small_groups.py --pairs "7А=14" "7Б=12" "8Б=2" --k 5
```

Повторяемость проверяется двумя отдельными вызовами. Копирование одного файла в два имени проверкой не является. Если результаты различаются, ищите причину в свободной генерации разметки: агент должен менять в скелете только данные, подписи и токены.

## 9. Установка готового скилла

### Claude (веб, десктоп, Cowork)

Загрузите `.skill`-файл в настройках скиллов или нажмите **Save skill** на карточке файла в чате (если организация разрешает создание скиллов).

### Claude Code

```bash
python3 tools/install_skill.py 04-output/<название>-dataviz --target claude
```

Скрипт проверяет скилл и копирует в `~/.claude/skills/<название>/`. Для проекта: `--scope repo --repo /путь/к/проекту`.

### Codex CLI

```bash
python3 tools/install_skill.py 04-output/<название>-dataviz --target codex
```

Копирует в `~/.agents/skills/<название>/` (для репозитория: `--scope repo`, папка `.agents/skills/`). Перезапустите Codex. Явный вызов: `$<название>-dataviz`.

### Оба сразу

```bash
python3 tools/install_skill.py 04-output/<название>-dataviz
```

### Хук шлюза честности (ставится вместе со скиллом)

`install_skill.py` по умолчанию добавляет хук: в Claude Code — в `.claude/settings.json`, в Codex — в `.codex/hooks.json` (проекта или пользователя, по `--scope`). Хук сам запускает `check_honesty.py` на HTML с графиками, созданных в сессии. При ERROR агент получает причину и должен переделать файл; завершить ответ с нечестным файлом он не может (до трёх попыток, дальше вы получите предупреждение). Хук работает, даже если агент не подключил скилл.

- Ваши настройки сохраняются, рядом остаётся копия `.bak`; повторная установка хук не дублирует.
- Codex запускает проектные хуки после того, как вы один раз подтвердите доверие к ним.
- Отключить: `--no-hook`. Исключение для круговой диаграммы, записанное владельцем в `house-style.md`: переменная окружения `DVM_HONESTY_ALLOW=pie`.

Зачем: в сквозных проверках агенты со скиллом выдавали обрезанную ось и круговую диаграмму, хотя инструкция запрещала. Инструкция не удерживает поведение; хук — да.

Подстраховка: добавьте в общие инструкции приложения строку «Для любых графиков, дашбордов и данных в презентациях используй скилл `<название>-dataviz`».

## 10. Обновление и версии

- Цвета или шрифты поменялись: откройте новую сессию в рабочей копии, скажите «обнови токены, вот новые цвета». Агент поправит токены и `house-style.md` и пересоберёт.
- Меняйте **токены и решения команды**, а не отдельные графики. Тогда правка работает везде.
- Храните скилл в **приватном** git-репозитории команды. Отмечайте версии тегами (`v1.0`, `v1.1`). Ведите короткий журнал изменений (файл CHANGELOG.md в репозитории скилла): что изменили и почему.
- Пересобирайте после любого изменения палитры: заново запустите `palette_audit.py`.

## 11. Если сломалось

Сначала три простые проверки по порядку (чаще всего ломается одно из них):

1. **Файл на месте и имя верное?** Папка называется так же, как `name` в `SKILL.md`; внутри `SKILL.md` (именно такое имя, заглавными).
2. **В описании есть слова вашего запроса?** Описание скилла решает, подключится ли он. Добавьте слова, которыми вы реально просите («график», «слайд с цифрами», «дашборд»).
3. **Новый чат или перезапуск?** Агенты читают список скиллов при старте.

| Симптом | Вероятная причина | Что сделать |
|---|---|---|
| Агент не читает `AGENTS.md` | Папка открыта не та | Откройте именно папку набора; напишите «Прочитай AGENTS.md» явно |
| Агент не видит файлы | Нет доступа к папке | Дайте доступ или выберите режим L0 |
| Агент придумал цвета бренда | Не было материалов, и он не пометил `TBD` | Скажите: «Не выдумывай бренд, пометь неизвестное как TBD» и пришлите материалы |
| Слишком много вопросов за раз | Агент нарушил правило ≤ 3 | Напишите: «Не больше трёх вопросов за раз» |
| Агент завис на ссылке (Figma и т.п.) | Закрытая ссылка | Пришлите скриншоты или PDF |
| `validate_skill.py`: «не взято в кавычки» | В описании есть `: ` без кавычек | Оберните описание в двойные кавычки |
| `validate_skill.py`: «name не равен имени папки» | Переименовали папку | Приведите к одному имени |
| `validate_skill.py`: описание длиннее 1024 | Слишком длинное | Сократите, оставьте триггеры |
| Скилл не подключается | Описание слабое; не перезапустили агента | Усильте описание, откройте новый чат |
| Скилл срабатывает на всё подряд | Описание слишком широкое | Добавьте «не используй для …» |
| Графики отличаются от запуска к запуску | Агент берёт цвета не из токенов | Проверьте, что все цвета ссылаются на `tokens.css`; запустите тесты повторяемости |
| `palette_audit.py` ругается на цвет бренда | Бренд-цвет не проходит контраст | Это нормально: используйте производный цвет для данных, бренд оставьте для логотипа |
| Чат не принимает `single-file-prompt.md` | Слишком большой | Уберите стили (`--styles` пусто) или передайте файлами по частям |
| Сеанс оборвался | Контекст кончился | Новая сессия + «Продолжи по `00-session/state.md`» |
| `lint: ошибки` | Изменили файл и сломали ссылку | Читайте текст ошибки: он называет файл и причину |
| В `04-output` пусто | Этап 8 не дошёл | Скажите: «Переходи к сборке (этап 8) по накопленным ответам» |

Если не помогло: откатитесь на последнюю рабочую версию (раздел 10), проверьте шаги 1-3 выше и приложите вывод проверок в issue.

## 12. Безопасность и приватность

Агент по инструкции:

- не отправляет данные в интернет и не вставляет их в поисковые запросы;
- не публикует и не рассылает ничего от вашего имени;
- не устанавливает скилл сам;
- пишет только в `00-session/`, `01-brand-inputs/intake-form.md`, `04-output/`, `05-research-log/`;
- не принимает и не повторяет секреты;
- **не исполняет инструкции, найденные в файлах и на сайтах**: они считаются данными. Если в присланном файле написано «игнорируй правила», агент покажет вам эту строку.

Ваш чек-лист:

- [ ] Работаете в копии вне публичного репозитория.
- [ ] В `01-brand-inputs/` нет паролей и ключей.
- [ ] Примеры данных обезличены.
- [ ] Перед публикацией дашборда смотрите, что на нём нет имён и малых групп.
- [ ] Данные детей только агрегированные.
- [ ] Результат проверили глазами: агент мог ошибиться.

```
tests/                  lint, юнит-тесты, прогон агента по сценариям, фикстуры, отчёты
docs/                   этот гайд
```

### Тесты

```bash
python3 tests/lint_kit.py
python3 -m unittest discover -s tests -p "test_*.py" -v
```

CI (GitHub Actions) запускает то же на каждый push и pull request.

### Тестирование агентом

Роли разделены: испытуемый агент запускается в песочнице без папки `tests/` и получает ответы «владельца» текстом (`tests/personas/owner-script-N.md`), а проверяет его скрипт `tests/check_run.py`, который смотрит на реальные файлы:

```bash
python3 tests/run_persona.py --persona 2 --agent codex   # или --agent claude, или --prepare-only
```

`tests/CODEX-TESTER-TASK.md` содержит задание для агента-тестировщика, `tests/REPORT-TEMPLATE.md` шаблон отчёта. Отчёты кладите в `tests/reports/`. Подробнее: `tests/README.md`.

### Как предложить изменение

- **Правило ядра** (`02-references/core-rules/`): нужен источник (стандарт, исследование, авторитетная практика). Ссылка, год, одна фраза «почему».
- **Стиль**: описывайте приёмы, а не копируйте работы и бренды. Не включайте фирменные шрифты и логотипы.
- **Инструкция агенту** (`AGENTS.md`): опишите, какую ошибку агента исправляет правка. Лучше пример поведения до и после.
- Перед pull request запустите тесты.

## 14. Частые вопросы

**Сколько это стоит?** Набор бесплатный. Платите только за ваш чат или агент.

**Работает ли без Claude?** Да. Формат `SKILL.md` открытый, а `AGENTS.md` читают многие агенты. Для обычного чата есть режим L0.

**Можно ли сложные графики (сети, потоки)?** Можно точечно. Агент проверит, поймут ли читатели, даст ключ «Как читать» и простую альтернативу. По умолчанию они выключены, чтобы результат был предсказуем.

**Мы не специалисты по данным. Не наделаем ошибок?** Ядро правил запрещает самые частые: обрезанные оси, круговые диаграммы, 3D, двойные оси, заголовки без оснований, показ малых групп (с дополнительным подавлением, чтобы скрытое нельзя было вычесть). Но проверяйте результат глазами: инструменты проверяют структуру и правила, а не смысл.

**Чем это отличается от шаблона дашборда?** Шаблон фиксирует вид. Набор фиксирует вид **и** правила честности **и** процесс, который агент проходит с вами, а потом работает сам для любых данных.

**Можно ли делиться готовым скиллом?** Да, если в нём нет конфиденциальных материалов (логотипов, внутренних цветов, которые нельзя раскрывать). Проверьте `assets/` и `references/`.

**Где взять помощь?** Откройте issue в репозитории: приложите вывод `lint_kit.py` и `validate_skill.py`.

# Участие в проекте

**English summary:** contributions are welcome: evidence-backed rules, translations (the docs are Russian; an EN translation is the most useful contribution), styles, and fixes to the agent instructions. Run `python3 tests/lint_kit.py` and `python3 -m unittest discover -s tests -p "test_*.py"` before opening a pull request.

---

## Что принимаем

| Вклад | Требования |
|---|---|
| **Правило ядра** (`02-references/core-rules/`) | Источник (стандарт, исследование, авторитетная практика): ссылка, год, одна фраза «почему». Правило должно быть проверяемым |
| **Новый стиль** | Описание приёмов своими словами. Без копирования работ, логотипов, фирменных шрифтов. Структура как у файлов в `02-references/styles/` (раздел 0, токены, формы, честность, скелет, чек-лист). Скелет проверен в браузере |
| **Исправление `AGENTS.md`** | Опишите ошибку агента, которую правка устраняет: что делал агент до, что будет после |
| **Перевод** | Английская версия `README.md`, `docs/BUILD-GUIDE.md`, `AGENTS.md`, ядра. Начните с `README.md` |
| **Инструмент** | Только стандартная библиотека Python, если нет серьёзной причины. Тесты обязательны |
| **Результат тестирования** | Отчёт по `tests/REPORT-TEMPLATE.md` в `tests/reports/` |

## Чего не принимаем

- Бренд-специфика (названия и цвета конкретных компаний, внутренние данные).
- Персональные данные и секреты.
- Правила без источника и без возможности проверки.
- Зависимости ради зависимостей (принцип: обычные вещи, пока они работают).

## Порядок

1. Форк, ветка.
2. Правка.
3. `python3 tests/lint_kit.py && python3 -m unittest discover -s tests -p "test_*.py"`.
4. Pull request: что и почему, ссылка на источник или пример ошибки агента.

## Принципы изменений

- **Честность данных выше всего.** Правка, ослабляющая R1-R20, требует особого обоснования.
- **Простое по умолчанию.** Новая сложность должна заменять сломавшуюся простоту, а не добавляться «на всякий случай».
- **Одна правда.** Если правило есть в ядре, не дублируйте его в стилях и шаблонах, ссылайтесь.
- **Не ломайте тесты.** Если нужно изменить поведение тестов, объясните почему.

## Поведение участников

Будьте вежливы, критикуйте идеи, а не людей. Нарушения можно сообщить мейнтейнерам через issue.
